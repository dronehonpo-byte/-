## ★1. 要件定義書 §4.4 ルール3「レ(D)」の弦の誤記

要件定義書の「0 vs 4」同音3ケースの記載：

| 音 | 記載 | 正しい物理 |
|---|---|---|
| レ(D) | 「D線の0 **または A線の4**」 | **G線の4**（A線4th は E であり D にならない） |
| ラ(A) | 「A線の0 または D線の4」 | ○ 正しい |
| ミ(E) | 「E線の0 または A線の4」 | ○ 正しい |

第1ポジションで第4指は開放弦の完全5度上＝**一つ下の弦の開放弦と同音**になります。
- D線開放(D) = **G線**第4指
- A線開放(A) = D線第4指
- E線開放(E) = A線第4指

したがって「レ(D)」は **G線の第4指**が正しく、本文の「A線の4」は誤記と判断しました。
実装は正しい **G線4** を採用し、`__tests__/stringJudge.test.ts` に回帰テストを入れています。
→ **この解釈で問題ないかご確認ください。**（必須テストケースはミ(E)の例だったため、レの例は明示されていませんでした）

## 2. 弦判定エンジンの実装範囲（§4.4）

- R1〜R5 を優先順位順に純粋関数で実装（`lib/stringJudge.ts`）。
- 第1ポジションを中心に、上位ポジションは近似で補助的に扱う（教則本レベル＝ほぼ第1〜第3で十分想定）。
- 高度なポジション最適化（イザイ等の高難度曲）は将来機能。今回は「自動判定＋手動修正」で担保する前提（§7）。

### R3 必須テスト（実装済み・緑）
- E線0 vs A線4、次が Fis(高) → **E線0**
- E線0 vs A線4、次が D(低) → **A線4**
- フレーズ末尾（次なし）→ **第4指(4)**

## 3. 指番号配置（§4.6）の距離ルール

- 条件②（元楽譜が下部印字）・③（重音の下）はデータのフラグで確定判定。
- 条件④（距離しきい値）と①（上部スペース不足）は**元画像のジオメトリ**に依存するため、
  現状は bbox から簡易推定（`lib/pipeline.ts` の `contextFromBBox`）。
  しきい値は `FINGER_LABEL_DISTANCE_THRESHOLD_PX`（既定48px）で調整可能。
- ★例外（松葉・強弱記号と重なるなら上へ）は実装済み。連桁・棒の長さの精密判定は
  OMR の座標精度に依存するため、**提供4曲での実測後にしきい値を微調整**する想定です。

## 4. OMR：外部AI API → OSS（Audiveris）へ移行

**背景**：従来は外部 Vision API（従量課金）で画像→JSON化していたが、ランニングコストを
抑えるため、対応をスキャンデータ限定にしたうえで OSS の楽譜認識に置き換えた。

- **構成**：`services/omr/`（Audiveris + Node ラッパーを Docker 化）でスキャン→**MusicXML**。
  `app/api/omr/route.ts` は `OMR_SERVICE_URL` へ転送し、返った MusicXML を
  `lib/musicXml.ts` で `Note[]`（§0スキーマ）へ変換する。外部AI/Vision APIは不使用。
- **対応形式**：PDF・スキャナ由来の PNG/JPEG のみ。スマホ撮影写真は非対応（`lib/scanQuality.ts`
  で簡易判定し警告）。カメラ撮影オプションは廃止。
- **認識前提**：傾きなし・影/光ムラなし・300dpi以上・白背景に黒音符（`services/omr/README.md`）。

### ★4-a. 座標換算はフェーズ2でキャリブレーション要
MusicXML は音高・小節・運指は正確だが「元画像のピクセル座標」を直接持たない。
`lib/musicXml.ts` は 小節幅の累積＋default-x と、音部記号＋音高の五線幾何から tenths 位置を求め、
ページ寸法(tenths)と画像ピクセル寸法の比でピクセル換算している（1ページ=1スキャン前提の近似）。
**実際のAudiveris出力を見ながら `CALIBRATION` 定数で合わせ込む**のが次段階の作業。

### ★4-b. 「楽譜に書かれた指番号」の扱い変更
OSS OMR は印字/手書きの指番号・ローマ数字の読み取りが弱く、多くは `null` になる想定。
そのため R1/R2（記載指番号・記載弦を尊重するルール）は実質的に働かず、
**運指は判定エンジンの自動計算が基本**になる（音高・符頭位置は取得できるので色分け・半音・音源は動作）。
記載を尊重したいケースは、ユーザーの手動修正（§4.8）で補う。

- デバッグ用に画面下部で解析JSONを確認できます（`DebugJson`）。

## 5. 音源（§4.9）

- Tone.js の簡易シンセで音高列を等間隔（四分音符相当）に再生。テンポスライダー付き。
