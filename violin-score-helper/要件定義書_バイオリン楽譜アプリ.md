## 1. 案件概要

### 1.1 背景・目的
バイオリンの初級〜中級の生徒が、楽譜を見ただけで「どの弦で・どの指で・どこが半音か」を直感的に理解し、練習用音源に合わせてゆっくりから弾けるようにする学習支援アプリ。指導者が生徒に渡す教材として使う。

### 1.2 ゴール（成功の定義）
楽譜写真をアップロードすると、次がワンストップで得られる状態：

- 使用する弦が色で分かる
- 指番号が分かる
- 半音の位置（および指を密着させるか否か）が分かる
- その曲の音源が鳴り、テンポを落として一緒に弾ける
- 自動判定が外れても、タップで手直しできる

### 1.3 基本方針
画像認識・楽譜解析・運指判定が絡むため、**「100%全自動」ではなく「自動判定＋手動修正」で実用ラインに乗せる**ことを設計の前提とする（顧客と合意済み）。

## 2. スコープ

### 2.1 対応範囲（含むもの）
- 楽譜画像のアップロード（スマホ撮影／スキャン画像、1ページ単位）
- 楽譜画像の読み取り → 構造化データ化（音高・小節・座標・既存の指番号/ローマ数字/強弱記号/スラー等）
- 弦判定ルールエンジン（本書 §4.4）
- 弦の色分け表示（蛍光マーカー風・音符が透ける／元画像に重ねる）
- 指番号の自動表示＋配置ロジック（上/下の切替、本書 §4.6）
- 半音マーク（^ / v）の表示・向き自動判定・色（青/水色）自動判定・表示切替（本書 §4.7）
- 手動修正機能（タップで弦・指番号を変更、下流のマークを再計算）
- 練習用音源の生成・再生＋テンポ調整
- 結果の保存・書き出し（PNG画像／PDF）
- 運指モードの切替（①おまかせ／②開放弦優先）＋①内での独自ルール指定
- 初回起動時のチュートリアル／使い方ガイド

### 2.2 対応範囲外（今回は含まない）
- 複数ページ楽譜の一括処理（1ページずつでよい：顧客合意済み）
- 弦名文字（G/D/A/E）のテキスト表示（顧客「しない」）
- 指の形パターン表示（2-3密着=橙／1-2密着=水色のマーカーライン）→ **将来機能**
- イザイ無伴奏ソナタ等の高難度曲の高精度対応 → **将来機能**
- 完璧な演奏音源（今回は練習確認用の簡易音源まで：顧客合意済み）
- 楽譜内容の楽典的な誤り検出・自動校正

## 4. 仕様詳細

### 4.1 対象楽譜・入力
- 入力：スマホ撮影画像・スキャン画像（JPEG/PNG）。1ページ単位。
- 楽譜の複雑さ：**単音メロディ中心**、たまに重音（ダブルストップ）。
- 想定ジャンル：バイオリン教則本（鈴木バイオリン教本／新しいバイオリン教本）、クラシック、映画・ジブリ曲。
- テスト用に提供済みの曲：リーディングのコンチェルト／ホーム・スイート・ホーム／マジャールの踊り／バッハ Vn協奏曲No.1 第1楽章。**これらを判定精度の基準サンプルとする。**

### 4.2 使用環境・非機能要件
- スマホ・PC全対応のレスポンシブWebアプリ。
- オンライン前提OK（画像解析に通信を使ってよい）。
- 保存：PNG画像／PDF書き出し。
- 精度：「できる限り正確」が要望。ただし自動判定＋手動修正で実用ラインを担保。

### 4.3 弦の色分け（表示仕様）
- **蛍光マーカーペンのように、楽譜の音符がくっきり透けて見える**塗り方（半透明・乗算合成イメージ）。
- 音符（符頭）に直接色を付け、**元画像に重ねて表示**する。
- 例外：指番号が音符の上部と下部の2種類に分けて表示されている楽譜では、**それぞれの指番号の上に色付け**する。

| 弦 | 色（イメージ） | HEX |
|---|---|---|
| G線 | 茶（土） | `#8B5A3C` |
| D線 | 緑（葉・茎） | `#00BFA5` |
| A線 | 赤（花） | `#FF4081` |
| E線 | 黄（光） | `#FFD740` |

### 4.4 弦判定ルールエンジン（★最重要）

顧客支給ルールを厳密に実装する。優先順位はルール番号順。

**ルール1：楽譜上の明示指示（最優先）**
- 楽譜に指番号（0〜4）が記載されていれば、その指番号を**絶対使用**。
- 指番号がない音符は、**直前のポジションをそのまま維持**（勝手にポジションを変えない）。
- ただしポジションチェンジなしに演奏不可能な場合はルール2以降に従う。
- ポジションチェンジが必要な箇所には原則指番号が記載されている。不要な箇所にも指番号が付くことがある。

**ルール2：ローマ数字による弦指定**
- ローマ数字がある場合、下記で弦を固定：

| ローマ数字 | 弦 |
|---|---|
| Ⅰ | E線 |
| Ⅱ | A線 |
| Ⅲ | D線 |
| Ⅳ | G線 |

**ルール3：0 vs 4（開放弦 vs 第4指）の判定**
- 第1ポジションで開放弦と第4指が同音になる3ケース：
  - レ（D）：D線の0 または A線の4
  - ラ（A）：A線の0 または D線の4
  - ミ（E）：E線の0 または A線の4
- 判定：
  - 次の音が**現在より高い** → 開放弦（0）
  - 次の音が**現在より低い** → 第4指（4）
  - 次の音が**同音** → 次に変わる音の方向で判定
  - **次の音がない（フレーズ末・楽章末）** → 第4指（4）をデフォルト
- 実装検証用の必須テストケース：
  - E線0 vs A線4 で次がFis（E線1、高音）→ **E線0**
  - E線0 vs A線4 で次がD（A線3、低音）→ **A線4**

**ルール4：ポジション選択**
- 4-1：奇数ポジション優先。
- 4-2：第2ポジション回避（音域が第1ポジションに包含されるため自動提案では最後の選択肢。ただし楽譜に明示されていれば従う）。

**ルール5：トリルの運指**
- 基本：1-2トリル または 2-3トリルを優先。
- 3-4トリルは原則回避。
- 例外：前後の流れ上3-4以外に選択肢がない場合のみ許可。

**運指モード（切替UI）**
- ①おまかせ（一般的な初級〜中級の運指）
- ②開放弦優先（第4指=小指の使用をなるべく避ける）
- ①モード内で、ユーザーが独自の運指ルールを指定できる余地を持たせる（初期は簡易でよい／将来拡張前提）。

### 4.5 重音（ダブルストップ）
- 両方の音に、それぞれの弦色を付ける。

### 4.6 指番号の表示位置ロジック

**基本原則**：指番号はデフォルトで「音符の上側（五線の上側）」に配置。

**下側に配置する条件（いずれか該当時）**
- 条件①：加線の多い高音域で、かつ上部にスペースがない場合（上の段の楽譜と衝突する場合）。
- 条件②：元楽譜（入力画像）ですでに指番号が下部に印字されている場合、それに続く音の指番号も下側に揃える（AI・画像認識で「指番号が音符の下」と判定されたら、そのレイアウトを尊重）。
- 条件③：重音（ダブルストップ）で、下の音に対する指番号は見やすさのため自動的に下側に配置。
- 条件④【最優先の距離ルール】：符頭と指番号の物理的距離が離れすぎる場合（連桁が重なる16分・32分の密集地帯／音符が低く棒が上に長く伸びる場合など）。連桁の有無に関わらず、**符頭から上部の配置予定位置までの距離が一定閾値（ピクセル基準）を超えたら、符頭に近い下側へ配置**する。目的は「指番号を常に符頭から最も近いフリースペースに置く」こと。

**★例外処理（条件④より優先）**
- 下側に配置した結果、音符直下のクレッシェンド・デクレッシェンド（松葉記号）や強弱記号（p/mf/f 等）と重なる場合は、**距離ルールより記号の視認性を優先**し、あえて符頭から離れてもスペースに余裕のある上側へ配置。
- スラー・タイなどの細い線は数字が透過して見えるため、重ねて配置して問題ない。

### 4.7 半音マーク（^ / v）

**紐付け**：指番号を表示するモードでは、半音マークは音符ではなく「指番号の数字」に紐付け、そのすぐ近くに表示する。

**向きの自動判定**
- 指番号が**上側**に配置 → `^`（山型）。位置は数字の上部（または対象2数字の間を跨ぐ形）。
- 指番号が**下側**に配置 → `v`（谷型）。位置は数字の下部（または対象2数字の間を跨ぐ形）。
- 目的：上下スペースを有効活用して隣段との衝突を防ぎ、数字とマークの一体感を高める。

**色の自動判定（切替：青のみ／青＋水色）**
- **青 `#006CD4`（指を密着させる）**：同じ弦の上で、隣り合う指番号へ順方向／並ぶ場合（1→2、2→3、3→4 およびその逆。同ポジション内で指をピタッと付ける動き）。
- **水色 `#6EE6FF`（半音だが密着させない）**：音程は半音だが以下いずれか。
  - A）同指での半音移動（クロマティック）：同じ指番号のまま音をずらす（1→1、2→2 等）。
  - B）ポジション移動（シフト）を伴う：数字が逆転して半音になる（例：3rd→1st の 2→1 での半音進行）。
  - C）移弦を伴う：隣り合う音で弦が変わる（例：3→0 で開放弦と指の間が半音）。
- **表示切替**：「青のみ表示」／「青＋水色の両方表示」をユーザーが切り替えられる。

### 4.8 手動修正
- 音符（または判定結果）をタップして、弦・指番号を変更できる。
- 変更後は、半音マークの向き・色など下流の表示を再計算して反映する。

### 4.9 音源生成・テンポ調整
- 読み取ったメロディを簡易音源で再生（練習確認用。完璧な演奏音源ではない）。
- テンポを変更できる（ゆっくりから合わせられる）。
- 読み取り精度に左右されるため、初期段階は「練習用の確認音源」として割り切る（顧客合意済み）。

### 4.10 保存・書き出し
- PNG画像で保存。
- PDFで保存。

### 4.11 初回起動ガイド
- 初回起動時に、操作方法を示すチュートリアル／ガイドを表示（アップロード→判定→修正→音源→保存の流れ）。いつでも再表示できるようにする。

## 5. 技術方針（実装の前提）

- フロントエンド：Next.js（App Router）＋ TypeScript ＋ Tailwind CSS。レスポンシブ。Vercelデプロイ想定。
- 楽譜読み取り（OMR）：**専用OMRライブラリでは手書き込み・撮影ムラに耐えられないため、Vision対応モデルのAPIで画像→構造化JSONに起こす方式を採用**（音高・オクターブ・小節・符頭のバウンディングボックス座標・既存指番号・ローマ数字・強弱/松葉・スラー/タイの検出）。**モックデータ・シミュレーションは使わず、実APIで実装する。**
- 判定ロジック：TypeScriptの純粋関数モジュールとして「弦判定」「指番号配置」「半音マーク」を分離実装し、ユニットテスト可能にする。
- 描画：元画像の上にSVG/Canvasで座標ベースのオーバーレイ。弦色は半透明（乗算合成）で符頭が透ける表現。
- 音源：Web Audioベースのシンセ（例：Tone.js）で音列を再生、テンポスライダーで速度調整。
- 書き出し：Canvas→PNG、およびPDF出力。

## 7. リスク・前提条件

- 楽譜写真からの読み取り精度は入力画像の品質に依存する。ピンボケ・傾き・影が強い画像は精度が落ちる。→「自動判定＋手動修正」で吸収する前提。
- 手書き込みの多い教則本ページは誤読が増える可能性がある。提供4曲で基準を作り、閾値・プロンプトを調整する。
- 弦判定は顧客支給ルールに忠実に実装するが、楽譜の書き方（版・出版社）により例外が出る。手動修正で最終担保。
- 音源は練習確認用。強弱・アーティキュレーションの再現は対象外。
- Vision APIの利用料は運用時に発生（BYOK or Miyabee管理は運用ドキュメントで整理）。
